# 类与对象学习笔记 (OOP 基础)

## 一、 类与对象的基础定义
* **类（Class）**：是对一类事物的抽象描述，相当于“图纸”或“模板”。它把属性（数据）和行为（方法）封装在一起。类本身不占用数据内存。
* **对象（Object）**：是类的实例化（具体造出来的东西），相当于根据图纸建出来的“房子”。每个对象都有自己独立的数据。
* **应用范围**：大型软件系统、游戏开发、业务建模、数据结构实现等。

## 二、 面向对象三大核心特性
1. **封装（Encapsulation）**：把数据和操作数据的方法捆绑，隐藏实现细节，对外只暴露安全的接口。用于保护数据不被随意篡改。
2. **继承（Inheritance）**：子类可以复用父类的属性和方法，并可以扩展。用于提高代码复用性，减少重复劳动。
3. **多态（Polymorphism）**：同一接口，不同对象有不同的实现。用于统一处理不同类型的对象，提高代码的灵活性和可扩展性。

## 三、 代码实战解析：游戏角色系统
为了直观体现以上特性，我编写了一个 `Hero` (英雄) 类系统。
以下是这两份代码中，各个部分所体现的“类与对象”核心功能：

### 1. 【类与对象】基础与生命周期
* **代码体现**：定义 `class Hero` 就是设计图纸。通过 `Hero* h1 = new Hero(...)` (C++) 或 `h1 = Hero(...)` (Python) 实例化了具体的角色对象。
* **生命周期**：包含了**构造函数**（`__init__` / `Hero()`），在对象诞生时初始化属性；包含了**析构函数**（`__del__` / `~Hero()`），在对象销毁时清理资源。

### 2. 【封装】保护数据安全
* **代码体现**：血量 `hp` / `__hp` 被定义为私有属性（`private` / 双下划线）。
* **功能说明**：外部不能直接修改血量（防止玩家开挂直接改血条）。必须通过公开的 `takeDamage()` 方法扣血，且该方法内部做了保护逻辑（血量最低为 0），保证了对象状态的合法性。

### 3. 【继承】代码复用与扩展
* **代码体现**：`class Warrior(Hero)` 和 `class Mage(Hero)` 继承了父类。
* **功能说明**：战士和法师不需要重新写名字、血量、扣血的代码，直接“白嫖”了父类的所有功能。在 C++ 中通过 `: public Hero` 体现，在 Python 中通过括号体现。

### 4. 【多态】同一接口，不同表现
* **代码体现**：父类有 `attack()` 方法，但子类 `Warrior` 重写为【旋风斩】，子类 `Mage` 重写为【火球术】。
* **功能说明**：将不同的角色放入同一个列表中，用统一的循环调用 `hero.attack()`。代码只写了一句，但战士和法师打出了完全不同的操作。这正是多态的魅力所在（C++ 中借助 `virtual` 虚函数和父类指针实现）。

### 5. 【类变量与类方法】共享数据
* **代码体现**：`server_name` / `total_heroes`。
* **功能说明**：无论创建多少个具体的角色对象，它们都属于同一个服务器，总人数也是全服共享的。这体现了类变量（静态成员变量）的特性，与对象特有的属性（如各自的名字）形成对比。
